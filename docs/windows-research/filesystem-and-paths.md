# Windows filesystem and path assumptions audit

Ticket: [#3 Windows filesystem and path assumptions audit](https://github.com/fktpp2022/pi-project-memory/issues/3) (wayfinder research for [#1 Windows support map](https://github.com/fktpp2022/pi-project-memory/issues/1)).

Status: research only. No product code was changed.

## Question

Which current assumptions in `src/paths.ts`, `src/store.ts`, `src/child-tools.ts`, and `src/restricted-bash.ts` break on native Windows?

## Method and host

- Read the four source files at commit `f88a96d` plus `src/config.ts`, `package.json`, and the Pi `1.4.0` package shell helpers.
- Ran live probes on the audit host with Node scripts under `%TEMP%\opencode\winfs\` (not committed). Probe IDs `P1`-`P12` below reproduce the command and the relevant output.
- Host: Windows 11 `10.0.26300.0` (x64), NTFS on `C:`, `D:`, `E:`; Node `v26.8.1`; Git `2.55.0.windows.5`; PowerShell `5.1.26100.9711`; Git Bash at `C:\Program Files\Git\bin\bash.exe`; Developer Mode enabled (`AllowDevelopmentWithoutDevLicense=1`); OneDrive at `C:\Users\Lenovo\OneDrive`.
- "Observed" means probed on this host. "Documented" means the linked primary source states it. "Not probed" is called out explicitly.

## Answer in one paragraph

The code is written for POSIX paths, POSIX permissions, POSIX rename-atomically-over-anything, and POSIX no-follow opens. On Windows the first breaks `resolveToolPath` for Git Bash `/c/...` inputs and for `rm` in `restricted-bash`; the second makes `0600/0700` cosmetic, so privacy depends entirely on the user-profile ACL; the third makes every publish fail with `EPERM` while any reader, editor, OneDrive, or indexer holds the target open, with no retry; and the fourth is silently unavailable because `O_NOFOLLOW` is `undefined` on Windows. Case-insensitive paths break the lexical `isContainedPath` and the case-sensitive `INDEX_FILE` exclusion, and long paths break child processes at 259 characters even though Node file APIs keep working past 260.

## Fact table

Severity: **blocker** = feature does not work on a normal Windows host; **major** = intermittent or security/privacy correctness; **minor** = confusing behaviour or narrow edge case.

### A. Path forms

| #   | Assumption                                                  | Windows behavior                                                                                                                                                                                                                                                                | Impact                                                                                                                                                                               | Recommended handling                                                                                                                                                  |
| --- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | `C:\...` and `C:/...` are the only Windows absolute forms.  | Both are absolute and `path.resolve` normalizes them (`P1`). `path === path.win32` on Windows.                                                                                                                                                                                  | No break for native-drive paths.                                                                                                                                                     | Keep native forms as the canonical output.                                                                                                                            |
| A2  | POSIX-looking absolute paths from Git Bash are not special. | `isAbsolute("/c/Users/x")` is true on win32, but `resolve(cwd, "/c/Users/x")` produces `C:\c\Users\x` (or `D:\c\...` when cwd is on `D:`), not `C:\Users\x` (`P1`). `resolveToolPath` therefore returns a non-existent sibling tree (`paths.ts:17-23`).                         | **blocker**: read/write/edit inputs copied from Git Bash output (`/c/...`), Cygwin (`/cygdrive/c/...`), or WSL (`/mnt/c/...`) never reach the memory directory and fail containment. | Normalize MSYS/Cygwin/WSL forms to a drive path before `resolve`; otherwise reject with a path-form hint. Settled map decision already requires normalizing `/c/...`. |
| A3  | Drive-relative input cannot change drives.                  | `resolve("D:\\proj", "C:foo")` is `C:\foo`; `resolve("D:\\proj", "C:")` is `C:\` (`P1`). Node documents per-drive working directories.                                                                                                                                          | **major**: a tool input can silently address another drive's current directory instead of the project.                                                                               | Reject drive-relative forms, or resolve them explicitly against the drive root with a warning.                                                                        |
| A4  | UNC paths and mapped drives are interchangeable.            | UNC is absolute and survives `resolve`/`realpath`; `realpath` of a `subst` drive returns the underlying drive path (`X:\...` -> `C:\...`, `P11`). `realpath` of `\\localhost\C$\...` stays UNC (`P11`).                                                                         | **major**: a memory root configured as `X:\...` or `\\server\share\...` is compared with a project root canonicalized to `C:\...`; lexical containment and namespace identity fail.  | Canonicalize both sides with `realpath` before comparison, and treat UNC and local views as distinct roots rather than aliases.                                       |
| A5  | `\\?\` and `\\.\` prefixes are not user input.              | `resolve`/`normalize` pass them through unchanged; `isContainedPath("C:\\proj", "\\\\?\\C:\\proj\\x")` is false (`P1`).                                                                                                                                                         | **major**: legitimate extended-length paths are rejected; a mismatched prefix can also make containment comparisons meaningless.                                                     | Strip `\\?\` and `\\.\` (including `\\?\UNC\`) or reject them at the tool boundary.                                                                                   |
| A6  | `~` expansion is the same everywhere.                       | `resolveToolPath` expands only `~` and `~/` (`paths.ts:19-20`); `~\x` becomes `<cwd>\~\x` (`P1`). `configuredMemoryDirectory` does accept `~\` (`paths.ts:82`). `file://` is expanded with `fileURLToPath` and works for `file:///C:/...` and `file://server/share/...` (`P1`). | **minor**: config and tool inputs disagree; `~\...` and `%USERPROFILE%` inputs fail.                                                                                                 | Share one expansion helper for config and tool paths; support both separators after `~`.                                                                              |
| A7  | Separators are a single character.                          | `path.win32` accepts both `/` and `\`; `basename`/`resolve` handle Git's forward-slash output (`P1`, `P7`).                                                                                                                                                                     | No break in normal Git path handling.                                                                                                                                                | Emit and compare with one canonical form (`\`), but accept both on input.                                                                                             |

### B. Case-insensitive containment, realpath, keys, display

| #   | Assumption                                                      | Windows behavior                                                                                                                                                                                                                                                                   | Impact                                                                                                                                                                            | Recommended handling                                                                                                      |
| --- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| B1  | Path containment can be decided lexically and case-sensitively. | `isContainedPath("C:\\Temp\\CaseRoot", "c:\\temp\\caseroot\\file.md")` is false; both names denote the same directory (`paths.ts:248-252`, `P2`). It is a false negative, not an escape.                                                                                           | **major**: read/write/edit/delete through a differently cased path (common from model output, editors, or lowercase drive letters) is rejected as "escapes the memory directory". | Compare with `path.win32` case folding plus a `realpath` check on both sides, or canonicalize every incoming path first.  |

| B3  | A memory file must literally end in lowercase `.md`.            | `assertContainedMarkdown` uses `endsWith(".md")` (`paths.ts:257`); `FOO.MD` is rejected even though it aliases `foo.md` on NTFS. `safeDeleteMemoryFile` has the same check (`store.ts:913`).                                                                                       | **minor**: users and tools that produce `.MD` cannot write or delete, with no Windows-specific explanation.                                                                       | Accept `.md` case-insensitively on Windows and canonicalize the on-disk name first.                                       |
| B4  | Long and 8.3 names are distinct.                                | `isContainedPath("C:\\proj", "C:\\PROGRA~1\\x")` is false when the root is the long name (`P1`); `realpath` resolves the short form to the long form.                                                                                                                              | **minor**: short-form paths inside the root are rejected.                                                                                                                         | Canonicalize before the containment test.                                                                                 |
| B5  | A segment containing `:` is either a drive or invalid.          | `assertContainedMarkdown` accepts `C:\mem\notes.md:stream.md`; Node creates an NTFS alternate data stream on `notes.md`, the directory listing does not show it, and fast-glob never scans it (`P10`). The write "succeeds" but the memory is invisible.                           | **major**: silent data loss; memory topics written to an ADS are never indexed or recalled.                                                                                       | Reject `:` in any segment after the drive prefix (also `::$DATA`).                                                        |
| B6  | The index is excluded by exact name.                            | NTFS is case-insensitive, so `memory.md` and `MEMORY.md` are the same file, but `scanTopicsInternal` excludes only the exact string `"MEMORY.md"` (`store.ts:192`). fast-glob `**/*.md` is case-sensitive, so `UPPER.MD` and `Mixed.Md` are not scanned (`P9`).                    | **major**: the index can be indexed as a topic (duplicate/self-referential context), while `.MD` topics silently disappear from recall and the prompt catalog.                    | Compare the index name case-insensitively and scan with a case-insensitive pattern (then dedupe by canonical path).       |
| B7  | VCS directory filtering is case/separator sensitive.            | `containsVcsMetadataSegment` splits on both separators and lowercases (`paths.ts:25-27`); scan/snapshot use the same idea (`store.ts:194`, `store.ts:867`).                                                                                                                        | No break; this is one of the few Windows-correct helpers.                                                                                                                         | Keep.                                                                                                                     |
| B8  | A sanitized project key stays short enough.                     | `sanitizeProjectKey` replaces every non-alphanumeric with `-` and caps at 200 characters plus hash (`paths.ts:74-77`). With the default agent root, a 200-character key yields a 250-character namespace and a 264-character `memory` path on this host (`P6`).                    | **major**: the memory path exceeds `MAX_PATH` for non-Node tools and for child processes (F2).                                                                                    | Budget the key from the actual agent root (or always hash long roots) so the full memory path stays under 259 characters. |
| B9  | Home-relative display matching is exact.                        | `displayPath` checks `path.startsWith(home + "\\")` (`paths.ts:244-246`); `c:\users\lenovo\...` and `C:/Users/Lenovo/...` are not shortened (`P1`).                                                                                                                                | **minor**: cosmetic only.                                                                                                                                                         | Compare case-insensitively after normalizing separators.                                                                  |
| B10 | `path.relative` behaves like `isContainedPath`.                 | `path.relative` is case-insensitive on win32 (`C:\Foo` vs `c:\foo\bar` -> `bar.md`, `P2`), but `isContainedPath` is not.                                                                                                                                                           | Inconsistent: some layers accept a path and the next rejects it.                                                                                                                  | Use one containment primitive everywhere.                                                                                 |

### C. Privacy, chmod, private directories

| #   | Assumption                                          | Windows behavior                                                                                                                                                                                                                                                                                                                              | Impact                                                                                                                                                                                                                                                                                                      | Recommended handling                                                                                                                                                                                                             |
| --- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | `chmod 0700`/`0600` makes a directory/file private. | Node documents that on Windows only the write permission is changeable and owner/group/other distinctions are not implemented. Probes confirm: after `chmod(0700)`, `stat` reports `0o40666`; after `chmod(0600)`, `0o100666`; `icacls` still shows inherited `SYSTEM:(I)(F)`, `BUILTIN\Administrators:(I)(F)`, and the user `(I)(F)` (`P3`). | **major**: every "private" claim in `ensureRealPrivateDirectory` (`paths.ts:113-119`), `ensurePrivateDirectory` (`paths.ts:224-233`), `publishFile` (`store.ts:409`), and lock creation (`store.ts:654`, `store.ts:741`) is false as a POSIX privacy claim. Privacy is only the inherited user-profile ACL. | Align with the settled map decision: document that Windows privacy relies on the user-profile ACL and remove/rescope `0600/0700` wording. Explicit ACL hardening remains out of scope; if kept, use `icacls` or native ACL APIs. |
| C2  | A "real private directory" check works for links.   | `lstat` reports a junction or symlink as `isSymbolicLink()` and neither file nor directory (`P5`). `ensureRealPrivateDirectory` rejects that (`paths.ts:115-117`), but `ensurePrivateDirectory(memoryDir, "Memory root", true)` follows links (`paths.ts:224-237`). `publishFile` rejects any symlink parent (`store.ts:405-406`).            | **major**: a memory root that is a junction/redirected folder initializes successfully, then every write fails with `Unsafe parent directory`.                                                                                                                                                              | Decide one policy: reject reparse points at startup with a clear error, or allow a user-configured memory root but not symlinked parents inside it.                                                                              |
| C3  | chmod can be used to clear attributes.              | Setting `0o444` sets the Windows read-only attribute; `rename` over that target fails `EPERM`, while `rm` of it succeeds (`P4`, `P4b`).                                                                                                                                                                                                       | **major**: an editor or user marking `MEMORY.md` read-only breaks all publishes until the attribute is cleared.                                                                                                                                                                                             | Clear the read-only attribute (or retry after `chmod`) as part of the publish recovery path.                                                                                                                                     |

### D. Hard-link publish and atomic rename

| #   | Assumption                                                   | Windows behavior                                                                                                                                                                                                                                                                                                                                                              | Impact                                                                                                                                                                                                                                                                                                | Recommended handling                                                                                                                                                                 |
| --- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | `link()` is available for exclusive create.                  | `fs.link` maps to `CreateHardLinkW` (`libuv fs.c:2772-2778`). Microsoft documents hard links as NTFS-only (`CreateHardLinkA`). Probe: works on NTFS and on a loopback SMB UNC share (`P4`, `P11`); FAT/exFAT and shares without hard-link support are expected to fail.                                                                                                       | **blocker** on FAT/exFAT/unsupported shares: new topic creation and `backfillIndex` (`exclusiveCreate = true`, `store.ts:416-426`, `store.ts:113`) return `EPERM`/`ENOTSUP` and the write fails.                                                                                                      | Fall back to `copyFile(temp, target, COPYFILE_EXCL)` (non-atomic for readers, but honest) when `link` fails with `EPERM`/`ENOSYS`/`ENOTSUP`/`EXDEV`; document the reduced guarantee. |
| D2  | A second publish of a new file is detected atomically.       | `link` to an existing target returns `EEXIST` (probe, `P4`), which `publishFile` maps to `false` and `atomicWriteIfBaseline` maps to "File was created while the update was staged" (`store.ts:422-424`, `store.ts:467-468`).                                                                                                                                                 | No break; works as designed on NTFS.                                                                                                                                                                                                                                                                  | Keep.                                                                                                                                                                                |
| D3  | `rename` replaces an existing file even if it is being read. | `fs.rename` is `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)` (`libuv fs.c:2340-2347`); Node documents that an existing `newPath` is overwritten. On this host, replacement fails `EPERM` if the target has **any** open handle, including a handle opened with `FILE_SHARE_DELETE`, and succeeds after the handle closes (`P4`). It also fails on a read-only target (`P4b`). | **blocker/major**: `publishFile` (`store.ts:427`) has no retry. A concurrent Pi session, editor, OneDrive sync, antivirus, or search indexer turns a memory write into a hard error. `withFileMutationQueue` is an in-process `Map` only (`file-mutation-queue.js:27-47`), so it cannot prevent this. | Bounded retry with jitter on `EPERM`/`EBUSY`/`EACCES`, clear read-only, then surface a specific "file is open in another process" error. Do not spin forever.                        |
| D4  | `rm` of an in-use file is equivalent to POSIX unlink.        | `rm` succeeds while a Node read handle is open (libuv uses `FILE_SHARE_DELETE`, `libuv fs.c:512`), but fails `EBUSY` while a handle without `FILE_SHARE_DELETE` is open (`P4`). `safeDeleteMemoryFile` has no retry (`store.ts:923`).                                                                                                                                         | **major**: deletes intermittently fail in the same conditions as D3.                                                                                                                                                                                                                                  | Same retry policy as D3; report the owning condition.                                                                                                                                |
| D5  | Temporary and target are always on the same volume.          | The temp file is created next to the target (`store.ts:407`), so `rename` is same-volume; cross-volume `EXDEV` is not normally reachable. The Android `copyFile` branch is not used on Windows (`store.ts:420`).                                                                                                                                                              | No break for the main path.                                                                                                                                                                                                                                                                           | Keep temp-in-parent; only add a cross-volume fallback if a configured memory root spans volumes.                                                                                     |
| D6  | The pre-hash namespace migration rename always succeeds.     | `rename(preHashBaseDir, compatibleBaseDir)` runs only if the compatible dir does not exist (`paths.ts:191-199`), but the whole block is `try {} catch {}`; an open handle or a non-empty destination fails silently.                                                                                                                                                          | **minor**: stale pre-hash state is left behind; the resolver still works because reservation follows.                                                                                                                                                                                                 | Log/ignore explicitly; do not treat migration as authoritative.                                                                                                                      |

### E. Symlinks, junctions, lstat, no-follow

| #   | Assumption                                                              | Windows behavior                                                                                                                                                                                                                                                                                                                                | Impact                                                                                                                                                                                                           | Recommended handling                                                                                                                                                         |
| --- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | `O_NOFOLLOW` prevents following links.                                  | `fs.constants.O_NOFOLLOW` is `undefined` on Windows (`P5`); Node's documented Windows flag set excludes `O_NOFOLLOW`. `NO_FOLLOW_READ` therefore becomes plain `O_RDONLY` (`store.ts:41`). | E2  | Creating links needs elevation, so link attacks are out of scope.       | With Developer Mode enabled, unprivileged `fs.symlink` succeeded on this host (`P5`); Microsoft documents `SYMBOLIC_LINK_FLAG_ALLOW_UNPRIVILEGED_CREATE` as requiring Developer Mode, otherwise admin/`SeCreateSymbolicLinkPrivilege`. Junctions created with `mklink /J` need no privilege (`P5`), and `lstat` reports them as symbolic links. | **major**: junction traversal is available to any process that can write the memory tree, without elevation.                                                                                                     | Treat reparse points in the memory tree as untrusted; verify `realpath` containment per file, not only per root.                                                             |
| E3  | `followSymbolicLinks: true` is safe because the memory root is private. | fast-glob with `followSymbolicLinks: true` traversed a junction and a symlinked file and returned `junction-dir/secret.md` and an outside file (`P9`); `scanTopicsInternal` uses `true` (`store.ts:183-189`). `snapshotMarkdown` uses `false` (`store.ts:863-868`).                                                                             | **major**: outside `.md` content can enter the prompt catalog/recall via a junction, while the dream diff does not see the same files (inconsistent view).                                                       | Scan with `followSymbolicLinks: false` and/or reject/reparse-check every result; make scan and snapshot agree.                                                               |
| E4  | `lstat` tells file vs directory.                                        | For a symlink/junction, `isFile()` and `isDirectory()` are both false and `isSymbolicLink()` is true (`P5`). Code paths that check `isSymbolicLink` before `isDirectory` are correct; code that only checks `isDirectory` can misclassify.                                                                                                      | **minor** on current code; a trap for future changes.                                                                                                                                                            | Centralize a "real directory" predicate.                                                                                                                                     |

### G. Locks, restricted Bash, child tools, packaging

| #   | Assumption                                           | Windows behavior                                                                                                                                                                                                                                                                                      | Impact                                                                                                                                                                                                            | Recommended handling                                                                                                                          |
| --- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | `process.kill(pid, 0)` is a reliable liveness check. | Signal 0 tests existence (Node docs). Probe: own PID alive; `999999` -> `ESRCH`; `4` -> `EPERM` (treated alive by `processIsAlive`, `store.ts:625-632`); PID `0` -> success/alive (`P8`).                                                                                                             | **major**: a recycled PID can make a stale lock look alive forever (no age cap beyond mtime), and a corrupt lock with `pid: 0` would never be reclaimed. | G2  | Lock file create/touch/delete is portable.           | `open(..., "wx", 0o600)`, `utimes` while a read handle is open, and `rm` while a read handle is open all succeeded (`P4`, `P8b`).                                                                                                                                                                     | No Windows-specific break found in the lock file mechanics themselves.                                                                                                                                            | Keep; the remaining risks are G1 and C1.                                                                                                      |
| G3  | `rm` operands are POSIX absolute paths.              | `parseDelete` requires `raw.startsWith("/")` (`restricted-bash.ts:59`), so `C:/...` and `C:\...` are rejected. | G4  | Bash sees Windows paths.                             | Git Bash `pwd` in a Windows cwd prints `/d/Projects/...` (MSYS form); `cygpath -w` converts back (`P7`). ## Findings that most affect the map's decisions

1. **Normalize path forms before anything else.** Git Bash `/c/...` is the single most damaging form because it is the form the background Bash tool naturally emits (`pwd`); it breaks both direct tool paths and `rm` (`A2`, `G3`, `G4`). The map already settled "normalize all common Windows path forms"; this audit supplies the exact mappings and the `resolve` behavior to test.
2. **Privacy must be documented as ACL-based, not mode-based.** `0600/0700` changes nothing observable except the read-only bit (`C1`). The map's settled decision is correct; the implementation must stop claiming POSIX privacy.
3. **Atomic replace must be retried, or the design must accept failures.** `MoveFileExW` replacement fails while any handle is open, even with `FILE_SHARE_DELETE` (`D3`); a one-line retry loop is not optional if multiple Pi windows/editors/OneDrive are supported. The map's open question "retry or document" should resolve to **retry with a bounded budget and a clear terminal error**.
4. **Hard-link publish needs a non-atomic fallback on non-NTFS.** New topic creation and index backfill are the only paths that use `link`; FAT/exFAT/unsupported shares otherwise cannot create memories at all (`D1`).
5. **Long paths are a child-process limit, not a Node fs limit.** Node works past 260, but `spawn`/Git fail at 259 and `git -C` fails "Filename too long" (`F2`). The memory namespace cap of 200 characters is too generous once the agent-root prefix is added (`F3`); support should either shorten keys or declare a 259-character contract.
6. **No-follow is not available on Windows.** `O_NOFOLLOW` is undefined and reads follow links (`E1`); junctions need no privilege (`E2`), and the topic scanner follows them (`E3`). This is the main security gap to close if the memory tree can be written by another local process.
7. **Case-insensitive filesystem vs case-sensitive code.** The index exclusion and `.md` suffix checks are case-sensitive (`B3`, `B6`); fast-glob silently drops `.MD` topics (`B6`). This is a correctness gap even on a healthy host.
8. **Packaging is still red.** `os` excludes `win32`, so a normal `npm install` refuses the package (`G7`).

## Explicitly not probed

- FAT/exFAT hard-link failure (no such volume on this host; documented as NTFS-only instead).
- Dehydrated OneDrive placeholders and Files On-Demand hydration behavior.
- A real mapped network drive (`net use`) and a non-loopback SMB server.
- Windows 10 22H2 and arm64; this host is Windows 11 x64.
- Case-sensitive directories enabled per directory (`fsutil file setCaseSensitiveInfo`).
- Long-path behavior of the Pi runtime itself beyond `spawn`/Git Bash probes.
